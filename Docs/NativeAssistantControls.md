# 原生听写、应用快照和助手配置

ChatGPT.app 与 Codex 在当前安装中使用相同的应用标识 `com.openai.codex`，共用 Codex 配置。

- L2：按用户选择使用 ControlDeck 通用听写，识别后填入当前聚焦的输入框；首次升级将旧原生听写 L2 迁移为通用听写，其他自定义 L2 不变。原生听写动作仍可手动选择，但此版本 ChatGPT 的按钮查找未验证可用。
- R2：模拟左右 Command 同时按下，触发用户确认的全局应用快照快捷键；不切换应用，以便截图当前台前应用。ChatGPT/Codex 需运行并启用该快捷键。
- 轮盘默认八格：Codex、网页浏览器、Cursor、Grok Bot、通用 macOS、Finder、终端、Slack。
- Cursor 和 Grok Bot 自动匹配各自应用；Cursor 的 L2 按住发送 Control+M，Grok Bot 的 L2 按住发送 Command+D，松开结束原生听写（快捷键来自用户提供的应用提示截图）。所有配置的 R2 均为全局应用快照。

升级首次启动会迁移未改动的 Claude/音乐默认轮盘槽，并按用户要求一次性将所有配置的 R2 统一迁移为应用快照。其他按键及自定义轮盘槽保持原样；迁移后仍可手动修改 R2。原有 Claude、音乐配置仍可在设置中选择。

原生听写只匹配目标应用当前窗口中唯一、启用且支持按下的按钮，按精确名称检查标题、说明和帮助文本。没有匹配、匹配不唯一、搜索超过复杂度限制时不执行操作；重复节点会去重，不可读分支不会阻止其他可读分支的搜索；不会退回到发送按钮、语音通话或猜测的快捷键。停止听写也要求仍处于启动时的窗口。

目前用户截图只确认了「听写」提示文字。「停止听写」及其他语言的候选文字尚未经过此版本应用的实际辅助功能树验证。代码和回归测试通过并不代表原生集成已经实测成功。若系统未暴露这些控件，或录音中按钮使用不同名称，状态栏会报告无法定位；需要真实控件名称补充适配。

## 安装后验证

1. 退出 ControlDeck，替换 Applications 中的应用，再启动。
2. 打开 ChatGPT/Codex 的输入框，确认 ControlDeck 当前配置为 Codex。
3. 先点击 ChatGPT/Codex 输入框，再按 L2 使用通用听写，检查识别文字是否填入；不会打开 ChatGPT 原生听写界面。
4. 保持要截图的应用在台前，使用绑定「Codex · 应用快照」的配置按 R2，检查是否捕获该应用。先松开实体键盘修饰键；若无动作，先确认手动同时按左右 Command 能否触发。所有配置的 R2 默认均为应用快照。
5. 打开轮盘，确认 Cursor 和 Grok Bot 两项；选中后松开 Options，会切换配置并请求激活或启动关联应用。通用 macOS 只换配置。未安装或激活失败会单独提示。

旧的已安装工具包不会自动覆盖：更新应用后重新使用安装工具按钮更新工具包，才能让其接受新增 `codexAppSnapshot` 动作。无需更改系统语言或清空已有配置。

## 系统 Games 干扰

应用在连接、回到前台及控制器自定义配置变更时重新请求禁用系统手柄手势。Apple 将此 API 定义为偏好，不能保证系统接受；后台输入监听也不提供独占访问。长按 L2 打开 Games 的硬件现象仍待复测，不能据此断定是 AeroSpace 或 L2 的系统默认动作。可在系统设置的 Game Controllers 中检查此控制器的自定义动作；本次未修改系统设置。

## 按键速查和 Bot 导航

轻按触摸板显示当前配置的全部按键、摇杆和触摸手势；支持滚动，20 秒后关闭。Grok Bot、Cursor 默认 □ 发送 ⌘⌥B 打开/切换右侧面板，L3 复制、R3 粘贴，△ 未分配；Codex 默认 □ 审查、△ 计划，显示内容以实际配置为准。

Grok Bot 配置下 ← 选择侧栏上一个 Bot，→ 选择下一个 Bot，↑ 收起当前 Bot 所在分区，↓ 展开该分区，到列表两端停止。适配只操作台前 Grok Bot 窗口中明确的 Bot 列表；当前 Bot 不明确或名称重复时提示失败，不会发送消息。旧普通方向键默认绑定会一次性迁移；旧 ↑ 上一个 Bot / ↓ 下一个 Bot 绑定也会一次性升级为分区收起 / 展开，其他自定义绑定保留。分区动作幂等，已经处于目标状态时不会反向切换。

Bot 导航仅在读取到目标 Bot 名称后报告成功。AXPress 未生效时，会对重新确认可见且属于台前窗口的按钮补一次点击；未确认或焦点变化时报告失败，连续请求在本次操作完成前不重复执行。

Grok 基于 Chromium：普通按钮直接读取 `AXExpanded` 也可能返回 `false`，因此不能凭返回值存在判定为分组。先用 `AXUIElementCopyAttributeNames` 确认控件声明支持 `AXExpanded`，再读取展开状态；否则按普通 Bot 按钮处理。回归测试覆盖所有普通 Bot 均返回 `false` 时的跨分组切换。

Cursor Agents 配置下 ←/→ 按侧栏顺序切换已展开区域中的可见会话，跳过折叠工作区（即使 Cursor 仍单独显示该工作区当前会话行）；↑/↓ 折叠/展开当前会话的工作区。Pin、Archive、More 和 New Agent 等附件按钮不参与会话导航，不自动展开其他工作区或加载更多。置顶会话若无法唯一定位所属工作区，分组操作提示不可用。普通方向键默认绑定一次性迁移，用户自定义绑定保留。仅对台前 Cursor Agents 窗口操作，并读取选中会话标签确认结果；未唯一识别时不点击。

三个 AI 配置的 ○ 统一发送（Cursor/Grok Bot 仅向对应台前应用发送 Return，需输入框已聚焦）。ChatGPT/Codex 的 ←/→ 按实际侧栏会话顺序导航（置顶、已展开项目、最近），L1/R1 改为 ⌘[ / ⌘] 返回/前进。保留 L2 听写与 R2 全局应用快照。轻按触摸板的速查浮窗支持再次轻按关闭，长按触摸板与 Options 转盘保持独立。


ChatGPT 侧栏导航读取当前安装 26.1007 的侧栏按钮和 `aria-current`，不再使用独立的 Codex 最近任务排序。项目标题、分页按钮和折叠项目内容不参与导航。源代码确认会话按钮带有独有的 class 标记；依赖 Chromium 通过 `AXDOMClassList` 暴露它。相同会话可能在项目与最近列表同时选中：优先使用上次导航的位置，否则从第一个选中行开始；跳过已选中的重复行。按下后须读回同一个辅助功能元素的选中状态才报告成功；元素被重建或状态无法确认时报告未确认，不凭同名会话猜测。保留台前窗口检查，AXPress 无效后只对同一可见且命中验证通过的按钮补一次点击。

ChatGPT 的控件暴露与物理手柄端到端仍需实测，当前工具不允许直接检查该应用界面；静态安装源码和结构测试不能替代此验证。Cursor 当前会话识别失败新增不含标题或内容的 `CursorNavigation` 日志，以定位实际失败阶段；尚未宣称修复该识别问题。


2026-10-14 实测日志定位并修复两处识别问题：Cursor 的无关深层分支不再让已经找到的侧栏/标签失效，目标子树读取仍有完整性检查；ChatGPT 读取到会话行却没有肯定的 AX 当前状态时，使用会话标题独有的 `text-[var(--color-text)]` 标记补充识别。菜单打开也会改变行背景，因此不能用背景色 class 判断当前会话。新增回归用例覆盖实际搜索流程的深度/预算，以及未选中、菜单打开和重复行的区分。手柄端到端效果仍待复测。


后续复测进一步确认：AX 会省略 ChatGPT 标题容器的样式，但会话按钮本身的精确 `bg-primary-ghost-hover` class 可读。因此仅在没有其他肯定选中信号、所有高亮均属于同名会话且会话菜单未展开时使用该标记；普通 hover class 不算选中，菜单焦点或展开的附件会阻止操作。Cursor 则改用主按钮的 `ui-sidebar-menu-button-trigger` 标记穿过包装层识别会话；无 class 元数据时仍要求标题与置顶/归档附件共同构成已知行结构。


后续运行日志确认 ChatGPT 的 AXPress 返回成功但不切换，实际通过命中验证的点击可以切换。导航现优先点击同一台前窗口中验证过的可见目标；部分裁剪行只使用滚动区域内的可见部分，完全不可见时仅在目标声明支持时请求滚入视野，再重新确认目标。切换期间忽略同类按键重复，不把“正在切换”作为错误显示。状态提示浮窗点击穿透，开始切换前撤下旧提示，以免遮挡点击目标。仍须读回同一目标元素的选中状态才报告成功。


## 2026-10-15：摇杆分工、统一剪贴板与映射页

默认左摇杆移动鼠标、右摇杆以普通方向键移动文本插入点；触摸板保持自然方向滚动。右摇杆主轴达到 38% 时立即一步，持续 350 毫秒后每 90 毫秒一步，回到 22% 内停止。只输出一个主轴方向，轴切换有滞回。应用切换、听写、教程、截图、组合键层、断连及配置变动清除重复；恢复前必须观测真实硬件回中。未聚焦可编辑文本时，普通方向键由前台应用按自身语义处理。设置可分别选择插入点、鼠标和滚动摇杆；同源时插入点优先于鼠标，鼠标优先于滚动。

## 2026-10-19：浏览器辅助功能树初始化与面板识别

故障日志中 ChatGPT 侧栏搜索仅访问 11–12 个节点，Cursor 仅访问 12–13 个节点且侧栏、面板、标签根均缺失；没有触及深度或节点预算。当前安装版本仍保留静态侧栏标记，但不能据此假定其运行时：ChatGPT 26.1013.40934 使用 Codex Framework 155.0.8059.80，二进制支持 AXEnhancedUserInterface，不支持 AXManualAccessibility；Cursor 3.25.9 支持后者。首版只请求 Electron 属性时，ChatGPT 返回 -25205，用户确认未恢复。

导航先尝试读取现有树，缺失时 Cursor 按 [Electron 官方接口](https://www.electronjs.org/docs/latest/tutorial/accessibility) 请求应用级 AXManualAccessibility，ChatGPT 按 [Chromium 实现](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/browser/chrome_browser_application_mac.mm) 请求 AXEnhancedUserInterface。Chromium 会延迟 2 秒启用，因此每 100 毫秒重试、最多读取 35 次；Electron 最多 8 次。同一进程成功请求后不重复设置，避免每次按键重置 Chromium 的启用计时。不改变 macOS 隐私授权，不启动 VoiceOver。焦点、窗口或 ChatGPT 菜单状态改变即退出，保留原有唯一识别与点击后读回验证。

Cursor 复测时界面树恢复，但仍报告当前标签不在 16 个侧栏会话中。Chats 与 Apps 共用 ui-tab-system-tabs__viewport，旧版选择第一个面板，可能把 Apps 标签当作会话。现在收集面板边界并识别唯一的 Chats 标签栏；到达任一面板的标签栏即停止该面板搜索。标签栏也位于 ui-tiling-panel-content 内容宿主内，该类不能作为正文裁剪边界。多个 Chats 面板保守拒绝，当前依赖英文 Chats 标签，其他语言及多聊天面板暂不声明支持。

回归覆盖异步就绪、Chromium 2 秒延迟、超时、焦点改变、取消、Apps 在前且聊天标签在内容宿主深层、仅 Apps、多 Chats，以及原有第 19 层标签栏。结构测试不能替代安装后的物理手柄复测。

安装第二版后，用户确认 ChatGPT、Cursor 均恢复。运行日志记录 ChatGPT 连续 2 次、Cursor 连续 4 次切换成功且读回确认。ChatGPT 的增强接口返回 -25208，但约 2 秒后完整树出现并完成导航，因此不能单凭属性设置返回值断定初始化失败；实际快照和切换后选中状态仍是最终依据。安装应用、交付应用及 ZIP 的 40 个文件一致，18 个保存配置不变。Grok Bot 使用独立的命名 Bot 列表与标题/选中状态解析，不经过 Cursor 的 Chats/Apps 面板选择。

## 2026-10-20：搜狗右 Option 通用听写

用户发现助手托管模式有延迟和崩溃后，改为其已配置的「长按右 Option」快捷键。ControlDeck 在 L2 按下时发送右 Option 按下，在松开时发送对应释放；由搜狗处理长按阈值、录音、识别和上屏。不会再次启动助手进程，不使用未公开命令参数、气泡轮询或搜狗云 API 凭据。事件采用 flagsChanged、键码 61 及 NX_DEVICERALTKEYMASK，以区分右/左 Option。只报告快捷键的按住/释放，不宣称录音已就绪或文字已成功插入。

发送前需要既有辅助功能授权，并拒绝在其他修饰键已按住时开始，防止形成意外组合键；重复按下或松开不重复发事件。按下前预先创建释放事件；切换服务、配置、应用、手柄断连和正常退出均释放右 Option。释放保留用户另外按下的修饰键及左 Option。

请先在搜狗启用长按右 Option 语音，聚焦目标输入框，按住 L2 后等搜狗显示录音就绪再说话。短于搜狗长按阈值的轻按不会开始录音。录音设备由搜狗选择；使用手柄麦克风时，在搜狗选择 DualSense Microphone。ControlDeck 继续提供现有 USB/蓝牙手柄麦克风通道，不更改 Mac 默认输入设备。搜狗自身的识别、上屏与响应时间仍由搜狗管理，需物理手柄实测。

### 右 Option 释放兼容性排查

用户复测发现右 Option 长按能启动、L2 松开后搜狗没有收到对应 KeyUp，真实键盘按下再松开可恢复上屏。后续修订使用 HID 系统事件源，在实际松开时新建释放事件，保留原生修饰键事件标志；启动前预留的释放事件仅作为分配失败时的后备。左 Option 是否仍按住依据左侧设备标志判断，不把合成右 Option 造成的通用 Option 键状态当作左键。新增日志仅记录控制器释放、发送事件的标志和键状态，不记录听写内容。修订后仍须搜狗运行日志和物理手柄复测确认，不能以事件构造测试替代端到端结果。

快捷键无法替搜狗选择录音设备。已有蓝牙日志可见手柄音频帧，仍对电脑讲话的原因需要核对搜狗的设备选择。搜狗必须显式选择 DualSense Microphone；ControlDeck 不修改 Mac 系统默认输入。USB 发布失败或没有有效手柄传输时拒绝开始，而不是静默使用电脑麦克风。
